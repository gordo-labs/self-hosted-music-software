# Contributing

This is a **directory**, not a ranking and not a feature war.

PRs are welcome from people who **maintain** a tool in this stack, or who can point to a verified official homepage and a real owned-library job (listen, tag, intake/acquisition, serve, cache, export, DJ analysis, multi-room, remote reach).

Merges are reviewed. Nothing here auto-publishes to [tapemusicsuite.com](https://tapemusicsuite.com).

## What to add

- One concrete product (or a tight peer group already on the same line).
- Official homepage or canonical source repo. No invented URLs. No `example.com`.
- Open **and** closed tools on the same plane. Paid clients and commercial DJ apps belong here if people actually use them on owned files.
- Honest **Strength** and **Weakness**. A PR that is only praise will be asked to name the hole (second catalog, ops tax, path fragility, desk-only state, etc.).

## What not to add

- Storefront-only streaming apps (the catalog lives in a vendor cloud).
- Hardware SKUs, page-turner pedals, or live-notation apps unless we open a dedicated vertical.
- “Better than X” tables, OSS sermons, or Tape-vs-the-field framing.
- Duplicate entries. Search `README.md` first.

## How to PR

1. Fork, branch from `main`.
2. Add **one** bullet (or fix **one** URL) in the matching section of [`README.md`](README.md).
3. Keep the existing shape:

   `- **[Name](https://official.example/)** — Strength: …. Weakness: ….`

4. Put the tool in the vertical it actually does (server vs phone client vs DJ vs mesh overlay). If it spans jobs, pick the primary job and mention the rest in the weakness.
5. In the PR template: your role (maintainer / user), homepage, and the job it covers.

Issues are fine for “should this exist here?” before you write the bullet.
